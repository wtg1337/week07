# 개인 앱 제안서

앱 이름: 아침 등교길 비 확인 앱
작성·수정 날짜: 2026-11-16

## 1. 문제·사용자·핵심 가치

- 첫 사용자와 사용 순간: 일주일에 4일(월~목) 등교하는 대학생이 아침 외출 직전
- 현재 해결 방법과 불편: 기존 날씨 앱을 보아도 지금 밖에 비가 오는지 정확하지 않아, 매번 창문을 열어 사람들이 우산을 썼는지 보거나 손을 내밀어 비를 직접 확인하느라 외출 준비 시간이 지체됨
- 확인한 사실: 기존 날씨 앱 정보만으로는 현재 집 앞의 실제 강수 여부를 확신할 수 없어 물리적인 확인 행동을 반복함
- 아직 확인할 가설과 질문: 다른 등교 학생들도 아침 외출 직전 기존 날씨 앱의 불확실성 때문에 창문 확인 같은 번거로움을 겪는지 사용자 인터뷰를 통해 확인할 예정
- 앱 사용 후 얻을 핵심 도움: 아침 출석 길에 창문을 열거나 밖을 직접 확인하지 않고도 현재 실제 비 착수 여부를 즉시 파악하여 외출 준비 시간을 줄임
- 사용자 스토리: 일주일에 4일 등교하는 대학생이 현재 강수 상태 확인과 수동 새로고침을 해서 외출 전 우산 지참 여부를 빠르게 결정하기를 이루고 싶다.

## 2. MVP와 범위

| 기능 | 필수·보류·제외 | 이유 |
| --- | --- | --- |
| 현재 강수 상태 카드 표시 | 필수 | 창문을 열지 않고도 현재 비 여부와 우산 안내를 한눈에 확인하는 핵심 가치 전달 |
| 수동 새로고침 (상태 갱신) | 필수 | 사용자가 외출 직전 원하는 시점에 최신 상태를 직접 조회하는 핵심 행동 |
| 시간대별·주간 기상 예보 | 보류 | '지금 실제 비가 오는지' 판단하는 MVP 범위 이후에 검토할 기능 |
| 비 오기 전 푸시 알림 | 보류 | 백그라운드 타이머 및 복잡한 상태 처리가 필요해 핵심 흐름 검증 후 고려 |
| 유료 기상 API, 로그인, 서버 동기화 | 제외 | 학생 1명 개발 및 계정·서버·외부 패키지 제외 제약 조건 초과 |

## 3. 제약과 결정

- 실행 환경과 확인 상태: Flutter 실행 환경으로 계획하며, 현재는 기획 단계로 실제 앱 실행 및 정적 분석은 미실행 상태임
- 시간·인원·사용할 기술: 학생 1명이 단계별로 개발하며, 배운 Flutter 기본 위젯과 StatefulWidget(setState) 상태 처리만 사용
- 저장 위치와 유지 기간: 앱 실행 중의 메모리 변수에만 상태를 유지하며, 앱을 재시작하면 초기 상태('비 옴')로 돌아감
- 외부 서비스와 개인정보 범위: 계정, 백엔드 서버, 유료 기상 API, 외부 패키지를 일체 사용하지 않으며 실제 위치나 개인정보도 수집하지 않음
- 중요한 선택의 상황·선택지·결정·영향: [상황] 짧은 시간 안에 핵심 이용 흐름과 상태 변화를 먼저 검증해야 함 → [선택지] 유료 기상 API 연동 / 기기 로컬 저장 / 메모리 기반 가상 데이터 토글 → [결정] 서버·API 없이 메모리 변수(`bool _isRaining`)를 '비 옴 ↔ 비 안 옴'으로 단순 토글하고 1초 가상 로딩(`Future.delayed`)을 적용함 → [영향] 실제 기상 관측 데이터 대신 시뮬레이션으로 동작함을 명시하고, 예측 가능한 테스트 환경을 확보함
- 개발 규칙 세 가지와 각각의 확인 방법:
  1. 변수명과 함수명은 `lowerCamelCase` 규칙을 따른다 (`Effective Dart` 스타일 대조 및 코드 점검)
  2. 로딩 중(`_isLoading == true`)에는 새로고침 버튼을 비활성화하여 중복 실행을 막는다 (새로고침 연타 테스트 확인)
  3. 코드 작성 및 변경 뒤에는 반드시 정적 분석과 화면 동작을 함께 점검한다 (`flutter analyze` 및 실제 실행 확인)

## 4. 화면·데이터·상태

- 핵심 흐름: 앱 실행 → 초기 강수 상태 및 최신 확인 시각 확인 → 새로고침 버튼 선택 → 1초 로딩 후 갱신된 비 여부 및 시각 확인

| 화면·영역 | 사용자 행동 | 바뀌는 값·다음 상태 |
| --- | --- | --- |
| 상단 앱바 | 화면 진입 | '아침 등교길 비 확인' 타이틀 표시 (변화 없음) |
| 강수 상태 카드 영역 | 앱 초기 진입 | `_isRaining = true` 기준으로 '지금 밖에 비가 옵니다!'와 우산 아이콘·안내 문구 표시 |
| 강수 상태 카드 영역 | 새로고침 클릭 (로딩 중) | `_isLoading = true`로 바뀌며 로딩 인디케이터(`CircularProgressIndicator`)와 '최신 날씨 확인 중...' 표시 |
| 강수 상태 카드 영역 | 1초 로딩 완료 후 | `_isLoading = false`, `_isRaining = !_isRaining`으로 반전되어 '지금 비가 오지 않습니다' 상태 표시 |
| 최신 확인 시각 영역 | 새로고침 완료 시 | `_lastUpdated`가 현재 시각으로 갱신되어 '오전/오후 HH:mm' 형식으로 업데이트 |
| 수동 새로고침 버튼 | 버튼 클릭 | 로딩 중에는 비활성화(`null`)되었다가 1초 후 다시 활성화됨 |

| 데이터 필드 | 자료형 | 예시 | 규칙 |
| --- | --- | --- | --- |
| `_isRaining` | `bool` | `true` | `true`면 '비 옴', `false`면 '비 안 옴'을 뜻하며 초기값은 `true`로 시작 |
| `_isLoading` | `bool` | `false` | 새로고침 시작 시 `true`, 1초 지연 완료 후 `false`로 복귀 |
| `_isError` | `bool` | `false` | 조회 실패·예외 시 `true`가 되며 정상 새로고침 시 `false`로 초기화 |
| `_lastUpdated` | `DateTime` | `DateTime.now()` | 화면에 출력할 때는 '오전/오후 HH:mm' 문자열 포맷으로 변환하여 표시 |

- 빈 상태·잘못된 입력·실패 안내 중 필요한 것: 가상 데이터 조회 실패나 예외(`_isError == true`) 발생 시 카드 영역에 *"강수 상태 정보를 불러올 수 없습니다"* 안내 문구와 재시도 유도 UI를 표시하고, 기존 마지막 상태값을 유지함

| --- | --- | --- | --- | --- |
| AC1 | 앱을 처음 실행해 메인 화면에 진입 | 초기 가상 데이터 기준의 강수 상태('지금 밖에 비가 옵니다!')와 우산 안내 문구, 초기 확인 시각이 표시된다 | 첫 진입 화면의 아이콘·텍스트·시각 출력 확인 | 미실행 |
| AC2 | 메인 화면에서 '지금 상태 새로고침' 버튼을 선택 | 1초간 로딩 인디케이터가 표시된 후, 강수 상태가 반전('지금 비가 오지 않습니다')되고 최신 확인 시각이 업데이트된다 | 버튼 클릭 직후 로딩 표시 및 1초 뒤 상태·시각 변경 확인 | 미실행 |

| AC4 | 가상 데이터 처리 중 예외가 발생한 상태에서 새로고침 선택 | 에러 안내 문구가 표시되며, 기존에 표시되던 마지막 강수 상태 값이 유실되지 않고 유지된다 | 예외 유발 후 에러 안내 표시 및 기존 상태 유지 여부 확인 | 미실행 |
